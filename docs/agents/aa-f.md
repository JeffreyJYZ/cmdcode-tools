# Lane F notes — `oduse` live price list

Measured facts and traps from the lane that made the OpenDesign catalogue resolve at run time. Recorded here, not in `AGENTS.md`.

## The endpoint

- `GET https://amr-api.open-design.ai/api/v1/public/model-prices` — **public**. No key, no cookie, no account header. 200 with `{"data":[{"model":"<wire id>","pricing":{...}}]}`; 46 rows on 2026-11-17, 50 on 2026-11-20.
- Per row: `pricing.unit:"1m_tokens"`, `currency:"USD"`, `input`, `output`, `cacheRead`, `cacheWrite` (24 of 46), `longContext{inputTokensAbove, input, output, cacheRead, cacheWrite}` (9 of 46). The long-context key names are the same ones `core/od.json` uses, so `od::LongContext` deserialises the payload directly — one type, no conversion.
- The payload publishes **no multiplier, no label, no plan caps**. Those stay the baked file's, and nothing in the merge invents them.
- `oc-cmd-compare/src/data/sources/od/` does **not** fetch this at run time: it reads `od.generated.ts`, a checked-in copy of `core/od.json` regenerated by `scripts/extract-od-rates.ts`. The lane brief's "mpc already reads them at runtime" is therefore wrong; only the envelope shape was worth copying.

## The merge

- Two halves, merged field by field: rates/cache/long-context from the price list; caps/labels/`catalogId`/multiplier from `core/od.json`.
- A live row with no baked row is **counted, not listed** (`rowsUnlisted`): there is no published multiplier for it, and pricing it at 1× would be inventing one. The sets were identical (46/46) on 2026-11-17; by **2026-11-20 the live list had 50 rows** — `gemini-4-hydrogen`, `gemini-4-neon`, `gpt-6.2-astra`, `gpt-6.2-sol` — so `rowsUnlisted` reads 4 in practice, and a turn on one of them stays unpriced until `core/od.json` gains the row.
- `Model.live_rates` (`#[serde(skip)]`) is the per-row flag the JSON surfaces read to say `ratesFrom: "price-list" | "builtin"`.

## Cache

- `~/.cache/cmduse/od-model-prices.json`, `$CMDUSE_CACHE_DIR` moves the directory. Body written **verbatim**; the file's mtime is its age, and `Provenance.at` is derived from it (`now − age`).
- TTL 6 h, `--cache <dur>` (`30s`/`30m`/`6h`/`2d`, bare = seconds), `0` disables read and write.
- Written only after the payload parsed to at least one usable row. An empty `{"data":[]}` is an `Err` from `merge`, so it can never be persisted and then answer every run inside the TTL.
- Written to `<file>.<pid>.tmp` then renamed, so a torn write cannot leave a half body that parses to nothing.
- An **expired** cache is not a fallback: the answer is the baked seed marked `builtin`. Serving stale rates while claiming `live` is the failure this lane exists to prevent. The same applies to a corrupt cache body: `merge` fails, the transport is asked, and a failed fetch still lands on the seed.
- The catalogue is resolved **once per process** (`OnceLock`). A watch loop keeps that table until restart; a new run picks up a changed cache or fetches.

## Transport

- 8 s timeout, `User-Agent: oduse/<version>`, one retry on a transport error or a 5xx, none on a 4xx (`ureq::Error::Status(code, _)` inside 400..500).
- `ureq`'s error string carries the request line (and so the URL); only the cause is reported, the same rule `snapshot.rs::short_error` follows.

## Provenance

- `od::Catalog.provenance` is `#[serde(skip)]` and defaults to `builtin`, so the baked parse is never silently promoted.
- `od::install(catalog)` (a `OnceLock`) is the process-wide table; `od::catalog()` returns it, else the baked seed. That is why every renderer kept working without a signature change: they already called `od::catalog()`.
- One shared `render::catalog_json()` object feeds `-1 --json`, `plans --json` and the statusline's three scalar keys, so those surfaces cannot drift. `statusline_json` reads its `catalogSource`/`catalogAt`/`catalogAgeSecs` out of that object.
- Surfaces: the frame's dim `catalogue:` line, the `catalog` object in `-1 --json` and `plans --json`, `catalogSource`/`catalogAt`/`catalogAgeSecs` in `statusline --json`, the `{catalog}` template placeholder, the `ratesFrom`/`multiplierFrom` fields per model row, and the heading of `plans`/`models` text output.
- The key names (`source`/`at`/`ageSecs`/`error`, `catalogSource`/`catalogAt`/`catalogAgeSecs`) were aligned with the parallel ocuse lane's catalogue rather than invented fresh; oduse adds `rowsLive`/`rowsUnlisted`/`ratesFrom`/`multipliersFrom` on top.

## Flags

- `--no-catalog` and `--cache <dur>` are stripped by `oduse::args::split_catalog_flags` **before** the shared `cli.rs` parser, the same seam `--session-cookie` and `model <id>` use. `cmduse/src/cli.rs` belongs to another lane and was not touched; a future shared `--cache` for ocuse/arkuse/cmduse can move into `cli.rs` and this seam then deletes itself.
- `--cache` must name a unit or a bare number of seconds; a bad value exits 2 rather than silently reading zero.

## Gate note

- The shared tree was mid-edit in `cmduse/src/ocuse/**` during this lane, so bare `cargo clippy --all-targets -- -D warnings` stops on their `manual_contains` and `needless_borrow` before reaching a final verdict. Run it with those two lints allowed (`-A clippy::manual_contains -A clippy::needless_borrow`) to prove this lane's files are clean; a red gate naming `ocuse/**` is not this lane's file.
- Do not format the whole workspace while another lane is mid-edit — `rustfmt` on the specific `cmduse/src/oduse/**` files only, never `cargo fmt --all` (which writes).
